# Deploying the search service on AWS

Terraform for the service in `src/server.ts`: the hybrid retriever (BM25 + embeddings) over
Postgres + pgvector, behind a load balancer, with metrics, alarms and a dashboard.

```
internet ─► ALB (HTTP :80) ─► ECS Fargate task ─► RDS PostgreSQL 16 + pgvector
                                   │
                                   └─► CloudWatch Logs ─► metrics (embedded metric format)
                                                          ├─► alarms ─► SNS ─► e-mail
                                                          └─► dashboard
```

**Status: validated, not applied.** CI runs `terraform fmt`, `validate`, `tflint` and a Trivy
configuration scan on every push, and the container image is built, started and probed in
`image.yml`. CI has no AWS credentials, so it does not run `plan` or `apply`. Until someone has run
the steps below, treat the stack as untested against a real account.

## What it creates

| Piece | Why |
|---|---|
| ECS cluster, Fargate service (1 task, 1 vCPU, 2 GB) | the search API, `/healthz` and `POST /search` |
| Application Load Balancer | public entry; health check on `/healthz`, which never touches the database |
| RDS PostgreSQL 16, `db.t4g.micro`, 20 GB gp3, encrypted | pgvector and the BM25 tables; the password is generated by RDS and kept in Secrets Manager |
| Task definition `rag-ingest` | run once by hand: downloads SciFact, embeds it, fills the database |
| Security groups | internet → ALB → tasks → database, each hop open only to the one before it |
| Execution role | pull the image, write logs, read one secret. The containers have no role of their own |
| Log group, 5 alarms, SNS topic, dashboard | see below |

Not here, on purpose: no NAT gateway (it would cost more than the rest), no HTTPS (it needs a
domain), no remote state, no autoscaling. The Trivy exceptions in `.trivyignore` say why for each.

## Observability

The service writes one JSON line per search in CloudWatch's
[embedded metric format](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Embedded_Metric_Format_Specification.html),
so `LatencyMs`, `Errors` and `Results` exist as metrics in the `RagSearch` namespace with no agent
and no API call, and every line stays readable in the log. Alarms:

| Alarm | Fires when |
|---|---|
| `rag-search-latency-p95` | p95 over 500 ms in 3 of the last 5 minutes |
| `rag-search-errors` | 5 or more failed searches in 5 minutes |
| `rag-search-alb-5xx` | 5 or more 5xx from the tasks in 5 minutes |
| `rag-search-unhealthy-hosts` | a task fails its health check for 3 minutes |
| `rag-search-db-cpu` | database CPU over 80% for 10 minutes |

A bad request (HTTP 400) is not an error: only a failed search counts, and the cause is logged but
never returned to the caller.

## Run it

You need an AWS account of your own (not root: use an IAM user or IAM Identity Center with
permissions for ECS, EC2 networking, ELB, RDS, IAM roles, CloudWatch, SNS and Secrets Manager),
Terraform 1.9 or newer, and the AWS CLI configured with a profile for that account.

1. **Set a budget alert first**: Billing → Budgets → a monthly cost budget of US$ 5 with an e-mail
   alert. A stack left running costs money every hour.
2. `cd infra && terraform init`
3. `terraform plan -var alarm_email=you@example.com` and read it. It should add 28 resources, 29 with the e-mail subscription.
4. `terraform apply -var alarm_email=you@example.com`. RDS takes 5 to 10 minutes. Confirm the SNS
   e-mail so the alarms can reach you.
5. Load the data: run the command in the `run_ingest` output, then follow the `ingest` stream of
   the `/ecs/rag-search` log group until it prints `built the BM25 tables`. Expect 10 to 20 minutes.
6. `curl -X POST "$(terraform output -raw url)/search" -H 'Content-Type: application/json' -d '{"query":"aspirin and heart attack","k":5}'`
7. Open the `dashboard` output, send a few dozen requests and watch the latency widget fill in.
8. **`terraform destroy -var alarm_email=you@example.com`**, then check in the console that the
   load balancer, RDS instance and ECS cluster are gone.

Rough cost while it runs, from the public price list as I remember it for us-east-1 and not
checked against the current one: about US$ 0.10 to 0.15 per hour for the load balancer, the task,
the database and the public IPv4 addresses, plus a few cents for the one-off ingestion. A few hours
is well under a dollar. Check the current prices and your account's free-plan rules before relying
on that.
